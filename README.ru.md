# Nexa — документация на русском

[English](README.md) · **Русский**

Nexa — современный двухпанельный клиент SFTP и FTP для Windows, написанный на
C++20 с использованием Qt 6 и libssh.

Текущая версия: **0.3.0 Preview**. Состав релиза описан в
[VERSION.md](VERSION.md), история изменений — в [CHANGELOG.md](CHANGELOG.md).

## Основные возможности

- выбор протокола в профиле подключения: SFTP поверх SSH или FTP;
- подключение к SFTP по паролю, приватному SSH-ключу, через SSH-агент или
  клавиатурный диалог — метод выбирается по списку, который объявляет сервер;
- FTPS с явным шифрованием (`AUTH TLS`): защищаются и канал команд, и канал
  данных;
- пассивный режим FTP с `EPSV` и `PASV`, листинг через `MLSD` с разбором
  вывода `LIST` для старых серверов;
- проверка SHA-256-отпечатка ключа сервера или его TLS-сертификата;
- сохранение недавних подключений и автоматическое восстановление сессии;
- защита сохранённых паролей средствами Windows DPAPI;
- автоматическое переподключение при обрыве соединения;
- восстановление последней открытой удалённой папки;
- двухпанельный интерфейс для локальной и удалённой файловых систем;
- загрузка и скачивание отдельных файлов и каталогов;
- рекурсивная передача и удаление каталогов;
- Drag and Drop между локальной и удалённой панелями;
- Drag and Drop из Проводника Windows;
- загрузка виртуальных файлов непосредственно из открытого ZIP-архива;
- создание файлов и папок, переименование и удаление через контекстное меню;
- удаление выбранных объектов клавишей `Delete`;
- фоновая загрузка каталогов и кэширование просмотренных директорий;
- навигация по «хлебным крошкам» с историей «назад» и «вперёд»;
- фильтр по имени и сортировка по любому столбцу в обеих панелях;
- отдельное соединение для передач: панели остаются отзывчивыми даже во
  время передачи на несколько гигабайт;
- очередь передач с прогрессом, скоростью и отменой каждого элемента;
- продолжение прерванной передачи с того байта, на котором она остановилась;
- политики перезаписи: продолжить, перезаписать, пропустить или переименовать;
- скачивание идёт во временный файл `.nexapart` и переименовывается только
  после успеха — незавершённый файл невозможно принять за целый;
- сохранение времени изменения и бита исполнения при передаче;
- асинхронная передача с окном до 64 SFTP-запросов;
- отображение прогресса, объёма и текущей скорости передачи;
- тёмная и светлая темы с запоминанием выбора (`Ctrl+T`).

## Поддерживаемые платформы

Основная целевая платформа — **Windows 10/11 x64**.

Код интерфейса и сетевого слоя в основном переносим, однако нативные функции
Drag and Drop из Проводника, извлечение файлов из ZIP и защита паролей DPAPI
реализованы специально для Windows.

## Быстрый запуск

Готовая переносимая сборка не требует установки:

1. Откройте папку релиза.
2. Запустите `Nexa.exe`.
3. Выберите протокол, введите адрес сервера, порт, имя пользователя и способ
   аутентификации.
4. Подтвердите отпечаток ключа или сертификата сервера.

Не запускайте Nexa от имени администратора без необходимости. Windows
может блокировать Drag and Drop из обычного Проводника в приложение с
повышенными правами.

## Подключение

Протокол выбирается в списке «Протокол»: **SFTP (SSH)** на порту 22 или
**FTP** на порту 21. При смене протокола порт по умолчанию подставляется
автоматически.

В поле сервера можно вводить:

```text
sftp.example.com
```

или полный адрес:

```text
sftp://sftp.example.com:2222
ftp://ftp.example.com:2121
ftps://ftp.example.com
```

Схема адреса переключает протокол сама, а `ftps://` дополнительно включает
шифрование.

Для SFTP поддерживаются:

- пароль;
- приватный SSH-ключ;
- приватный ключ с кодовой фразой.

Для FTP используется пароль. Флажок «Шифровать соединение (FTPS, AUTH TLS)»
включает явный TLS: команды и данные передаются в защищённом канале, а
отпечаток сертификата подтверждается так же, как ключ SSH-сервера. Без этого
флажка FTP передаёт учётные данные и файлы в открытом виде.

После успешного ввода подключение добавляется в список недавних. Секреты
хранятся в зашифрованном виде через Windows DPAPI и могут быть расшифрованы
только в текущей учётной записи Windows.

## Работа с файлами

### Drag and Drop

- перетащите файл или папку с левой панели на правую для загрузки;
- перетащите объект с правой панели на левую для скачивания;
- перетащите файлы или папки из Проводника на правую панель;
- файл можно перетащить прямо из открытого ZIP-архива Проводника.

Если объект отпущен над удалённой папкой, передача выполняется в эту папку.
Если объект отпущен на свободном месте, используется текущий удалённый каталог.

### Контекстное меню

Щёлкните правой кнопкой мыши по локальной или удалённой панели. Через меню
доступны загрузка, скачивание, создание файла или папки, переименование,
обновление и удаление.

### Горячие клавиши

| Клавиша | Действие |
|---|---|
| `Enter` | Открыть выбранную папку |
| `Delete` | Удалить выбранные объекты |
| `F2` | Переименовать выбранный объект |
| `F5` | Обновить текущую папку |
| `Alt` + `←` / `→` | Назад и вперёд по истории |
| `Alt` + `↑` | Перейти на уровень выше |
| `Ctrl` + `L` | Ввести удалённый путь вручную |
| `Ctrl` + `Shift` + `L` | Ввести локальный путь вручную |
| `Ctrl` + `F` | Перейти к фильтру по имени |
| `Ctrl` + `1` / `2` | Раздел «Файлы» / «Передачи» |
| `Ctrl` + `T` | Переключить тёмную и светлую тему |

## Очередь передач

Передачи выполняются по отдельному соединению, поэтому просмотр каталогов
не блокируется во время выгрузки или загрузки. Раздел «Передачи» показывает
прогресс, скорость и состояние каждого элемента; отменить можно как отдельную
передачу, так и всю очередь.

Поведение при существующем файле выбирается там же:

| Режим | Действие |
|---|---|
| Продолжить | дозагрузить прерванную передачу, совпадающие по размеру файлы пропустить |
| Перезаписать | всегда начинать заново |
| Пропустить | не трогать существующий файл |
| Переименовать | записать рядом как `имя (2).ext` |

Скачивание идёт во временный файл `.nexapart` и получает окончательное имя
только после успешного завершения, поэтому недокачанный файл невозможно
принять за целый.

## Автоматическое переподключение

Если сервер закрывает соединение во время навигации или передачи, Nexa
пытается создать новую сессию и повторить операцию. Прерванная передача
продолжается с достигнутого байта, а не начинается заново: по SFTP — смещением
в файле, по FTP — командой `REST`. Текущий профиль и последний удалённый путь
сохраняются между запусками.

## Сборка из исходников

### Требования

- CMake 3.24 или новее;
- компилятор с поддержкой C++20;
- Ninja;
- Qt 6.5 или новее: Core, Widgets и Network;
- pkg-config;
- libssh 0.12 или совместимая версия;
- Windows SDK.

Рекомендуемая среда — MSYS2 UCRT64 с Qt 6.

### Сборка Release

```powershell
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DBUILD_TESTING=ON
cmake --build build --parallel
```

Запуск собранного приложения:

```powershell
.\build\Nexa.exe
```

### Тесты

```powershell
ctest --test-dir build --output-on-failure
```

Текущий набор включает smoke-тест Drag and Drop в обе стороны с проверкой
Windows-формата `FileNameW` и модульные тесты правил докачки и перезаписи
файлов.

### Переносимая сборка

Скрипт собирает приложение, запускает `windeployqt` и копирует необходимые
runtime-библиотеки:

```powershell
.\scripts\build.ps1
```

Другую папку назначения можно указать параметром:

```powershell
.\scripts\build.ps1 -OutputDirectory dist-release
```

Результат:

```text
dist-release\Nexa.exe
```

## Безопасность

- перед первым подключением показывается отпечаток SSH-ключа сервера, а для
  FTPS — отпечаток TLS-сертификата;
- принятые ключи и сертификаты сохраняются и проверяются при следующих
  подключениях;
- изменение известного ключа или сертификата требует повторного подтверждения;
- соединение для передач открывается только с уже подтверждённым отпечатком;
- пароли и кодовые фразы защищаются Windows DPAPI;
- обычный FTP передаёт пароль и файлы открытым текстом — для внешних серверов
  выбирайте SFTP или включайте FTPS.

## Известные ограничения

- FTP работает только в пассивном режиме, активный режим не поддерживается;
- очередь передач не восстанавливается после закрытия приложения;
- файлы передаются по одному: параллельных передач пока нет;
- скорость ограничивается сетью, сервером и лимитами хостинга;
- файлы, перетянутые из ZIP, предварительно извлекаются во временную папку;
- полноценные установщики и автоматическое обновление пока отсутствуют;
- Linux и macOS пока не являются протестированными платформами.
