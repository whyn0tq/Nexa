## [1.0.0] - 2026-10-15

> [!IMPORTANT]
> Интерфейс и движок передач переписаны заново.

### <img src="docs/assets/brand/icons/plus.svg" width="22" height="22" alt=""> Добавлено

- Несколько серверов одновременно: каждый сервер открывается в своей вкладке
  со своими соединениями для просмотра и для передач. Открытые вкладки
  восстанавливаются при запуске.
- Сохранённые сервера с названиями и цветными метками, стартовая страница с
  быстрым подключением и палитра команд (`Ctrl+K`).
- Общая для всех сессий панель передач с прогрессом, скоростью, оставшимся
  временем, повтором и отменой, а также настройки параллельных соединений и
  правила перезаписи.
- Правило для файлов, которые уже есть (докачать, заменить, пропустить,
  переименовать), всегда на виду: метка в полосе передач, кнопки с простым
  пояснением в открытой панели и карточки в настройках. Варианты открываются в
  тех же матовых стеклянных меню, что и всё приложение, а не в системных
  списках.
- Файлы, брошенные в любое место окна сессии, загружаются в открытую папку
  сервера; если при перетаскивании задержаться над вкладкой, она откроется.
- Живая задержка для каждой сессии.
- Просмотр и правка файлов сервера на месте (`F4`): файл открывается в своей
  программе из временной папки, и каждое сохранение автоматически уходит
  обратно.
- Операции в локальной панели: удаление в Корзину, переименование, новая папка.
- Настройки (`Ctrl+,`) с редактором для просмотра и правки: по умолчанию
  Блокнот; если выбранного редактора нет — VS Code, затем Notepad++; любую
  другую программу можно указать по пути.
  `Delete` и `F2` работают в той панели, где фокус.
- Матовые стеклянные контекстные меню, размывающие окно под собой.
- Мгновенный просмотр и правка: выделенный мелкий файл скачивается в фоне,
  поэтому открывается без ожидания сети; иначе мелкие файлы читаются и
  сохраняются по уже открытому соединению за два обмена вместо нового входа.
  Уведомление показывает, сколько это заняло.
- Мгновенные папки: пока папка открыта, все её подпапки читаются заранее одной
  конвейерной пачкой, поэтому при открытии содержимое видно сразу, а на сервер
  уходит только тихая проверка.
- Быстрое подключение: вкладка сервера сразу показывает папку, где её оставили,
  из копии на диске, пока идёт вход. Живой список приходит вместе с
  «подключено»: начальная папка определяется, открывается и читается за два
  конвейерных обмена сразу после входа. Одно соединение для передач
  открывается заранее, поэтому первая загрузка или скачивание начинается без
  отдельного входа.
- Интерфейс на английском (США) по умолчанию и на русском в один клик:
  карточки языков с флагами в настройках, применяются быстрым перезапуском,
  который возвращает открытые вкладки. Даты и размеры следуют выбранному
  языку. `--language en|ru` выбирает язык из командной строки.
- `Nexa.exe --demo-shots <папка>` сохраняет скриншоты для README: выдуманные
  сервера из офлайн-соединения-заглушки, пустая выдуманная локальная папка и
  примеры передач во временном профиле настроек.
- `tests/transfer_bench.cpp` для замера скорости против настоящего сервера,
  `tests/connect_bench.cpp` для замера входа и первого списка папки и тесты
  кодека SFTP.
- Документация на английском и русском с оформлением, нарисованным по цветам
  и иконкам самого приложения (`scripts/brand-assets.mjs`).

### <img src="docs/assets/brand/icons/edit.svg" width="22" height="22" alt=""> Изменено

- Новый SFTP-клиент поверх SSH-канала: на одно соединение «в полёте» держится
  до 64 файлов и 24 МБ запросов вместо одного запроса за раз, а папки
  создаются, читаются и удаляются конвейерными пачками.
- Передачи идут по 1–16 параллельным соединениям на сессию (по умолчанию 4);
  файлы от 40 МБ делятся на части, которые переносят несколько соединений. FTP
  и FTPS используют ту же параллельную очередь.
- Увеличен буфер отправки сокета: на Windows значение по умолчанию
  ограничивало загрузку несколькими МБ/с, как только у канала появлялась
  задержка.
- Для SSH предпочитается AES-GCM.
- Меньше обменов при входе: сначала пробуется сохранённый пароль, ключ или
  агент, а не пустая проверка «none», а лимиты пакетов SFTP запрашиваются
  только перед первой передачей. Чтение папки отправляет следующие запросы
  только после ответа на предыдущие и больше не ждёт ответа на закрытие.
  При пинге 200 мс первый список папки теперь приходит примерно через 0,44 с
  после входа вместо 0,8–1,0 с, а вход занимает около 2,3 с вместо 2,5 с.
- Полностью новый вид: чёрный оникс, матовые стеклянные панели, красный
  акцент, свой заголовок окна с родным изменением размера, макетами Snap и
  скруглёнными углами, новая иконка.

### <img src="docs/assets/brand/icons/check.svg" width="22" height="22" alt=""> Исправлено

- `Delete` удалял выделение на сервере, даже когда файл был выделен в
  локальной панели. Удалённые записи теперь сразу пропадают из списка, а
  локальная панель обновляется, когда окно снова становится активным.
- Сессии больше не обрываются при простое: соединение просмотра пингуется,
  TCP keep-alive настроен, а разорванное соединение переподключается без
  ограничений после первого успешного входа. Прерванные файлы докачиваются с
  места остановки.
- Загрузка тысяч мелких файлов больше не ползёт со скоростью несколько файлов
  в секунду на каналах с большой задержкой.

### <img src="docs/assets/brand/icons/trash.svg" width="22" height="22" alt=""> Удалено

- Раскладка с боковой панелью и светлая тема.

## [0.3.0] - 2026-09-02

### <img src="docs/assets/brand/icons/plus.svg" width="22" height="22" alt=""> Добавлено

- Подключения по FTP наряду с SFTP: протокол входит в профиль подключения и
  запоминается вместе с недавними хостами.
- FTPS через явный `AUTH TLS`, защищающий и управляющий канал, и канал данных;
  для серверов, которые этого требуют, TLS-сессия переиспользуется на
  соединениях данных.
- Проверка сертификата сервера FTPS по SHA-256: отпечаток сохраняется и
  перепроверяется так же, как ключи SSH-хостов.
- Пассивный режим соединений данных через `EPSV` с запасным `PASV`, машинные
  списки через `MLSD` и разбор `LIST` для вывода Unix и DOS, если у сервера
  нет `MLSD`.
- Докачка по FTP через маркер `REST` с теми же правилами перезаписи и
  недокачанных файлов.

### <img src="docs/assets/brand/icons/edit.svg" width="22" height="22" alt=""> Изменено

- Работа с сессией вынесена за общий интерфейс воркера, поэтому панель
  просмотра, очередь передач и логика переподключения не зависят от
  протокола.

## [0.2.0] - 2026-08-01

### <img src="docs/assets/brand/icons/plus.svg" width="22" height="22" alt=""> Добавлено

- Отдельная SSH-сессия для передач, чтобы просмотр оставался отзывчивым во
  время больших загрузок и скачиваний.
- Очередь передач с прогрессом, скоростью, состоянием и отменой для каждого
  элемента.
- Возобновляемые передачи: прерванные скачивания и загрузки продолжаются с
  достигнутого байта, а не начинаются заново.
- Правила перезаписи (докачать, перезаписать, пропустить, переименовать) для
  каждой передачи.
- Сохранение времени изменения и бита исполнения при передаче.
- Вход через клавиатурный диалог и SSH-агент с учётом методов, которые сервер
  действительно предлагает.
- Светлая тема рядом с тёмной, выбор запоминается (Ctrl+T).
- Навигация хлебными крошками с историей «назад» и «вперёд» в обеих панелях.
- Фильтр по имени и сортировка по столбцам в обеих панелях.
- Заглушки для пустых папок и встроенная закрываемая область уведомлений.
- Модульные тесты правил перезаписи и докачки.

### <img src="docs/assets/brand/icons/edit.svg" width="22" height="22" alt=""> Изменено

- Ошибки показываются во встроенной полосе с короткой историей, а не отдельным
  модальным окном на каждую.
- Скачивание идёт во временный файл `.nexapart` и переименовывается после
  успеха, поэтому прерванную передачу нельзя спутать с готовым файлом.
- Деревья папок обходятся итеративно, держа открытым один дескриптор на
  сервере за раз, а не по одному на уровень.
- Лимиты SFTP согласуются один раз на сессию, а не на каждый файл.
- Цвета заданы дизайн-токенами в одном месте, а не строками внутри таблиц
  стилей.

### <img src="docs/assets/brand/icons/check.svg" width="22" height="22" alt=""> Исправлено

- Короткие чтения SFTP больше не портят скачанные файлы: конвейер
  выравнивается по реально полученному байту, а не по запрошенному.
- Файлы, размер которых сервер не сообщает, скачиваются полностью, а не
  записываются пустыми.
- Ошибка сервера во время чтения папки больше не принимается за конец списка,
  из-за чего он мог незаметно обрезаться.
- Удаление глубокого дерева больше не рискует исчерпать дескрипторы сервера или
  стек.

## [0.1.0] - 2026-07-29

### <img src="docs/assets/brand/icons/plus.svg" width="22" height="22" alt=""> Добавлено

- Переработанное рабочее пространство и визуальная система.
- Двухпанельный файловый менеджер: локальная папка и сервер.
- Вход по SFTP по паролю и приватному ключу.
- Проверка ключа хоста по SHA-256.
- Сохранённые учётные данные под защитой DPAPI.
- Автоматическое восстановление сессии и переподключение.
- Рекурсивные загрузка, скачивание и удаление.
- Конвейерное чтение папок сервера и упреждающее кэширование.
- Родное перетаскивание в обе стороны.
- Перетаскивание из Проводника Windows и виртуальных файлов из ZIP.
- Асинхронные передачи до 64 запросов «в полёте».
- Скрипт сборки переносимой версии для Windows.
- Открытая документация для разработки и инфраструктура проекта на GitHub.
